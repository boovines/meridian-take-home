# Draft review and frozen handoff

Implemented behavior; engineer generation and execution remain separate features.

A customer opens Review & comments, requests review, and sees the canvas become read-only. A missing workflow outcome creates a clarification thread; the supplied answer updates the workflow before analysis. Otherwise Temporal starts review in the background. Cancellation immediately unlocks the board and prevents late publication. Failed or abandoned queued/running reviews unlock after a recorded five-minute deadline is observed; the UI polls while active.

The OpenAI reviewer receives process content and discussion history. It can ask about ambiguity, inconsistent behavior, missing exceptions, and unnecessary steps. It cannot mutate the graph. Results are schema-checked and published in one transaction against the sealed draft revision. Invalid anchors or attempts to follow up a closed thread reject the publication. A closed concern can be represented by a linked new finding after process content changes; relevance of that change is judged by the reviewer prompt, not a deterministic semantic proof.

Findings use relational threads, messages and anchors. One response field supports a Reply, Resolve or Reject selection, with the response recorded as the comment or decision reason. The chip starts Open, becomes Answered after a customer reply, and shows Resolved or Rejected after that decision. Reopening resets it to Open; earlier replies remain in history. Sending Reply on an AI finding now incorporates the answer into the instructions of its active referenced blocks, then updates the canvas in place. The model may rewrite multiple anchored blocks in one response; only instructions can change. It must preserve unrelated requirements, route semantics and human approvals. The reply and all block changes commit atomically, with before/after instructions and revisions visible under View saved block changes. The finding stays Answered until the customer resolves or rejects it. The old proposal is cleared so it cannot replace the newly clarified instructions. Resolve and Reject still record decisions; they do not invoke a rewrite.

The rewrite is a bounded foreground request (90 seconds), with model calls outside SQL transactions. Publication checks the workflow content revision, target revisions, thread revision and editable state again. A concurrent edit, new review, timeout, invalid output or provider failure saves no partial reply/update; the response field remains available for retry. Request keys deduplicate committed retries, including a lost HTTP response. Concurrent uncommitted duplicate requests may both invoke the model, but publish only once; there is no durable background operation or automatic resume after a disconnected request.

Workflow-only/connection-only findings and removed targets retain the answer with an explicit manual-update explanation. Ambiguous answers or already-incorporated details can record no change; graph changes remain manual. These outcomes never claim a block update. Ordinary discussion notes remain comments. Updated instructions flow through subsequent review snapshots and the frozen graph used for generation; semantic changes still require a new review or explicit handoff acknowledgment. Model preservation of unrelated meaning is prompt-directed, not a deterministic semantic guarantee.

Messages have parent IDs and per-thread ordering. Resolutions and reopens append history. The customer must explain a manual resolution or rejection; accepting a detail suggestion changes only title/instructions and closes the finding atomically. A stale node revision rejects the entire operation. Ordinary customer notes do not block freeze. Removing a finding's only referenced node closes it with a deletion reason; other findings remain available for a decision.

Hovering a finding or discussion thread highlights its referenced blocks and connections on the canvas without changing the selected item. Keyboard focus within the thread does the same. Highlights clear when leaving the thread or closing the panel; workflow-wide comments highlight the whole graph. Referenced-item links remain available in a compact disclosure, including removed-item context.

Freeze requires a nonblank outcome, one Trigger, an explicit Outcome, reachable active blocks, valid endpoints and routing, paired nonoverlapping parallel sections, a completed review, and no open findings. Later semantic edits require acknowledgment or another review. Position-only changes do not require acknowledgment. The immutable snapshot contains the graph and review decisions. Database triggers protect the frozen graph and specification. Post-handoff revisions are outside this demo.

The workflow row serializes mutations to that workflow; other workflows proceed independently. Model calls occur outside SQL transactions. Review IDs, rather than shipment/process payloads, pass through Temporal. An activity can retry after worker failure; a completed publication is idempotent, and a duplicate API request key returns the original run. If initial dispatch fails, the board is unlocked with an actionable failure. Queued review rows also serve as durable dispatch intents: the worker reconciles them every five seconds with stable Temporal IDs. A crash between commit and dispatch is retried; a review whose deadline expires is marked failed instead of leaving the canvas locked.

Verification: reply tests cover multi-block atomic updates, before/after audit and frozen handoff, failed inference, stale inputs, cancellation, invalid targets/output, lost-response retries and manual outcomes. Browser tests verify immediate card updates, saved instructions on reopen, audit disclosure and preserved reply drafts on errors. Provider-contract tests use mocked inference; the local fixture rewrite does not establish live model quality. Existing persistence tests cover cancellation, stale application, goal clarification, history, deletion, rollback, deadline recovery, and frozen mutation rejection; graph tests cover loops and paired parallelism; browser tests cover two review rounds, approval, handoff and cancellation. CI uses an explicitly marked fixture reviewer. A separate live check verified Supabase → Temporal Cloud worker → OpenAI → persisted finding.

Known demo limits: review history displays the latest 20 runs; conversation pagination is deferred. Unsaved comment text is kept on request errors, but closing the panel discards it. Human comment creation supports the current selection or the whole workflow; AI findings can anchor multiple elements. No notifications, assignments, permissions, realtime collaboration or post-freeze edits are included.
